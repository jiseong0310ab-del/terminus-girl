# v0.14.0-rc1 · R1 이야기와 첫 동료 검증

2026-11-18. 프롤로그/거울역 도입 → 45초 단독 생존 → 마레 합류·일회 회복 → 75초 동행 생존 → 열차 대화/휴식까지 구현했다. 이는 첫 리빌딩 단계이며 지휘 덱·침식 선택·거울역 전체 사건 완성은 아니다.

- 전체 테스트 193개 통과. 이전155개에 새 이야기/파티/UI/저장 호환 회귀38개를 추가했다.

- 전투: 실제 update로45/75초 성공·보스 미등장·목표 구분, 마레 추종·피해1회 보호·12초 재준비·일반 보호막/대시/피격 무적과 상호작용·일시정지/카드 선택 동결.
- UI: 프롤로그부터 후일담까지 연결, 실패 재도전·기존 탐험 이어가기·저장 실패 안내/재시도·대화 기록·백업 설정·미저장 승리 중 업데이트 방지.
- 표시: 실제 마레 아틀라스 로드·그리기, 동행/보호 준비/재사용 표시. 화면/효과 감소에서도 필수 정보 유지.

## 입력 정책 시뮬레이션

`npm run qa:story`로 재현한다. seed1~30 ×5정책 =150회 여정(최대300전투). 정상 스폰·피해·경험치·제시 카드 선택을 사용하고 영구 정비는0이다. 입력/대시/카드 선택만 조작하며 HP·무적·킬·적 삭제를 변경하지 않았다. 결과 JSON은 output/에 생성한다.

| 정책 | 두 전투 완주 | 둘째 전투 평균 레벨 | 마레 보호 평균 |
|---|---:|---:|---:|
| 직진 | 30/30 | 1.40 | 0.07회 |
| 거리 유지+회수 | 30/30 | 4.80 | 0회 |
| 회수 중심 회피 | 30/30 | 4.93 | 0.03회 |
| 단순 방향 변경 | 30/30 | 4.27 | 0.50회 |
| 정지·카드 선택 | 14/30 | 3.24 | 2회 |

모든150회에서 지갑과 생존 탐험 통계는 변하지 않았다. 첫 시범은 이동만으로도 통과하기 쉬운 편이다. 보호가 발동하지 않은 완주도 많아 후일담에서 실제 발동을 단정하는 대사를 제거했다. 자동 난도 상향으로 보호 사용을 강요하지 않았으며, 향후 기록 확보/머무르기 임무에서 지원 가치를 확인해야 한다. 이 시뮬레이션은 재미·초보자의 이해도·아이폰 조작감 검증이 아니다.

## 공개 UI 확인 및 한계

공개 페이지의 버전 갱신·이야기 진입·대사 이동/재접속·전투 진입을 배포 후 확인해 이 절에 기록한다. 원격 브라우저의 프레임/시간 지연은 실기 성능 자료로 취급하지 않는다. 실제 아이폰에서 두 전투를 끝까지 플레이한 조작감·읽기·오디오·발열·오프라인 검증은 아직 남아 있다.


## 저장 버전과 구버전 캐시

새 저장은 envelope schema2이며 기존schema1 백업을 읽어 정상 이전한다. primary뿐 아니라 정상 backup도2로 기록한 뒤 완료한다. backup 쓰기가 실패하면 primary 이전을 진행하지 않는다. 변경 없는 저장도 backup1/missing을 보강하고, 정상2이면 불필요한 반복 쓰기를 하지 않는다. 이는 v0.13의 normal()이 새 story 필드를 버리는 하향 덮어쓰기를 막기 위한 조치다.

실제 fd80869의 이전 store.js를 별도 VM에서 읽어 검수했다. 새 primary2/backup2는 구버전이 모두 거부해 저장을 잠그며, 이미 열려 있던 구버전 탭은 변경 충돌로 쓰기를 차단한다. primary2+backup1 상태의 복구 우회도 재현했고, 새 no-op 저장으로 backup2를 보강한 뒤 차단됨을 확인했다. 자동 테스트는schema1 가져오기·backup 실패·복구/무쓰기·외래 버전 거부를 포함한다. 아주 짧은 완전 동시 탭 쓰기의 원자성은 여전히 보장하지 않는다.

이후 코드 롤백도schema2 읽기를 지원하는 저장 모듈과 새 서비스 워커 버전을 유지해야 한다. v0.13 저장 코드로 그대로 되돌리는 하향 배포는 지원하지 않는다.
