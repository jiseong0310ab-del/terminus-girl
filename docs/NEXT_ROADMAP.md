# 종착역의 소녀 · 다음 작업 로드맵

2026-11-17 · 기준: v0.9.3-rc1 공개 테스트 빌드

## 다음 목표

현재 구현된 첫 번째 장의 조작·저장·가독성·전투 균형을 검증해 무료 웹 정식 v1.0으로 출시한다. 자본금 0원·아이폰 1대 조건을 유지하며, 앱스토어는 빌드 환경과 예산을 확보한 뒤 별도 단계로 진행한다.

아래 버전 구분과 품질 목표는 다음 개발을 위한 제안이다. 현재 완료된 검증 결과와 앞으로 확인해야 할 항목을 구분한다. 출시일은 실기와 베타 결과를 바탕으로 정한다.

## 이미 구현한 범위

- 리제 4방향 대기·걷기, 자동 공격·대시, 적과 보스의 일러스트 아트
- 역 3개·일반 적 6종·정예 2종·보스 3종과 첫 번째 장의 결말
- 카드 16종·시너지 6종·유물 6종·선택 사건 6개·기억 기록 6개
- 열차 거점·영구 성장·마레 대화·소거 위험·탐험 정산
- 역 경계 이어하기·백업/복구·기록 이전·사운드·설정·설치 및 오프라인 캐시
- 자동 테스트 45개 작성 (CI 배포 통과 여부 별도 확인). 개발 환경의 Canvas 렌더링과 실제 데스크톱 Chrome에서 화면 전환·설정 저장·백업 내보내기·재접속·버전 갱신 후 기록 유지 확인

위 확인은 실제 아이폰 Safari·홈 화면 실행·장기 성능·외부 플레이 검증과 별개다.

코드 검토·아트 보정·문구 교정은 실기 피드백을 기다리는 동안 함께 진행할 수 있다. 전투 균형은 현재 규칙과 UI가 안정된 상태에서 맞춘다.

## 1. 안정화와 아이폰 실기

- 이동 중 대시, 두 손가락 유지, 손가락 이탈, 카드 선택 직후 입력을 점검한다.
- 잠금·앱 전환·전화 등 중단 상황 이후 일시정지와 오디오 복귀를 확인한다.
- Safari 주소창 변화·노치·홈 영역·화면 회전·작은 가로 화면에서 버튼이 가려지는지 확인한다.
- 새로고침·강제 종료·저장 용량 부족·손상 데이터·다른 탭의 변경 상황을 점검한다.
- 역 경계 이어하기와 현재 역 재시작 규칙을 플레이어가 이해하도록 안내를 보완한다.

개발 쪽에서는 코드와 재현 테스트를 준비하고, 실제 터치·발열·기기 복귀 여부는 아이폰에서 확인한다. 확인하지 않은 항목은 미완료로 유지한다.

## 2. 비주얼과 정보 전달

- 승인된 은청색 머리·남색 제복·금장·랜턴의 실루엣을 유지한다.
- 걷기 프레임의 발 위치, 모자·얼굴·머리카락·랜턴 크기와 흔들림의 일관성을 다듬는다.
- 피격·대시·사망 연출의 가독성과 실제 피격 범위를 맞춘다.
- 거울 유리역의 반사·설원역의 눈·종착 승강장의 시계와 열차 흔적을 더 선명하게 구분한다.
- HUD·체력·카드 설명·시너지 조건·유물 효과·소거 예고의 크기와 색 대비를 확인한다.
- 전투 결과에 도달한 역과 종료 원인이 잘 드러나도록 정리한다.

## 3. 전투·성장·스토리 조정

| 검토 대상 | 확인할 질문 |
| --- | --- |
| 첫 탐험 | 처음 온 사람이 이동·대시·경험치와 기억 조각의 차이를 이해하는가? |
| 카드와 시너지 | 선택이 실제 전투를 바꾸는가? 특정 조합만 지나치게 강하거나 약하지 않은가? |
| 적과 보스 | 공격 전에 읽을 수 있는 예고가 있는가? 여러 위험이 겹쳐도 회피할 여지가 있는가? |
| 소거율 | 위험을 피하고 기억을 복원하는 판단이 생기는가? |
| 영구 성장 | 반복 플레이로 변화가 느껴지는가? 강화가 없으면 진행이 막히지 않는가? |
| 사건과 유물 | 선택 간 장단점이 있고, 카드와 유물의 역할이 구분되는가? |
| 리제와 마레 | 역을 복원할수록 관계와 기억이 자연스럽게 이해되는가? 결말 뒤 재도전 동기가 있는가? |

승률·보상량·강화 비용은 실제 플레이 결과를 보고 조정한다. 자동 플레이의 성공률을 사람의 난이도 평가로 간주하지 않는다.

## 4. 모바일·PWA·저장 품질

- 현재 아이폰을 기준 기기로 삼아 30분 연속 플레이에서 발열·입력 지연·프레임·메모리 문제를 확인한다.
- 목표는 가능한 구간에서 60fps, 기준 기기에서 지속적인 30fps 미만 하락 방지다. 실제 측정 전에는 달성했다고 표시하지 않는다.
- Safari 첫 방문 → 홈 화면 추가 → 재실행 → 오프라인 실행을 순서대로 검증한다.
- Safari와 홈 화면 실행 각각에서 진행과 설정이 보존되는지 확인한다. 차이가 있으면 백업·복원 안내를 보완한다.
- 구버전 → 업데이트 알림 → 새 버전 열기 → 이어하기를 확인한다. 전투 중 강제 갱신과 서로 다른 버전의 파일 혼용을 방지한다.
- Safari에서 백업을 실제 파일로 받아 다시 복원하고, 잘못된 백업이 현재 기록을 바꾸지 않는지 확인한다.

## 5. 외부 베타와 출시 승인

권장 규모는 10명 내외의 소규모 테스트다. 가능하면 서로 다른 아이폰·iOS에서 첫 플레이와 재도전을 확인한다. 이는 모집 계획이며, 테스터를 모집하거나 초대를 발송한 상태는 아니다.

수집할 피드백은 첫 조작 이해, 첫 사망 이유, 카드 선택 이유, 보스 회피, 다시 하고 싶은 이유·그만둔 이유, 사용 기기·iOS·빌드와 재현 절차다. 현재 외부 분석 도구 없이 수동 피드백으로 시작한다.

우선순위:

- **P0:** 기록 손실, 진행 불가, 반복 크래시. 해결 전 출시 보류.
- **P1:** 조작·회피 판정·화면 가림·지속 성능 문제. 지원 기기에서 해결 후 출시.
- **P2:** 동작 어색함·문구·연출·경미한 배치 문제. 영향과 범위를 기록하고 수정.

출시 후보에서는 다음 조건을 모두 확인한다.

- [ ] 실제 아이폰에서 첫 번째 장을 끝까지 진행
- [ ] 미해결 P0·P1 문제 없음
- [ ] 자동 테스트와 수정된 항목의 회귀 검증 통과
- [ ] 저장·복원·업데이트·홈 화면 실행 확인
- [ ] 실제 플레이 화면과 일치하는 소개문·스크린샷·영상 준비
- [ ] 개인정보·저장 안내·지원 경로·아트/폰트/음원 사용 조건 확인
- [ ] 정상 빌드 보관·버전 태그·릴리스 노트·롤백 절차 준비

## 출시 후와 앱스토어

웹 v1.0 공개 후 첫 주에는 제보·완주·재도전과 저장 문제를 우선 확인한다. 이후 v1.1의 추가 사건·유물·동작 개선 등은 반응을 보고 우선순위를 정한다. 추가 장·플레이어 캐릭터·다국어는 후속 기획으로 둔다.

앱스토어는 예산·개발자 계정·macOS/Xcode 기반 빌드 환경 확보 → 네이티브 패키징과 저장/오디오/백업 검증 → TestFlight → 심사 자료·제출 → 승인·공개 순서로 진행한다. 과금 방식은 아직 확정하지 않는다.

4. 첫 역의 여러 빌드를 비교한 뒤 나머지 역·보스·영구 성장 수치 조정.
5. 실기 결과를 반영하고 소규모 베타로 이동.
